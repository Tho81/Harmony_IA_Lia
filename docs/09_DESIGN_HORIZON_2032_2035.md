# 09 · Design horizon 2032–2035

This page intentionally avoids a private development roadmap. It defines **public engineering questions** that a mature embodied assistant would need to answer during the 2032–2035 horizon.

## Structure
Can the body reduce distal mass while preserving fatigue life, stiffness where needed and serviceability?

## Actuation
Can joints provide sufficient torque density while remaining backdrivable/compliant enough for everyday human contact?

## Hands
Can manipulation combine tactile arrays, slip detection, force-position control and maintainable fingers without excessive complexity?

## Surface
Can a replaceable skin stack combine realistic contact, temperature behavior, tear resistance, cleanability and embedded sensing?

## Proprioception
Can the robot maintain a stable body schema under payload changes, compliant contacts, surface deformation and sensor faults?

## Social interaction
Can facial and whole-body motion communicate intent clearly without creating unsafe motion or uncanny unpredictability?

## Cognition
Can high-level AI remain powerful and updateable while safety-critical control remains isolated, auditable and deterministic?

## Compute envelope
Can onboard compute sustain multimodal perception, local model inference and body-state estimation with enough memory bandwidth and storage headroom, while keeping real-time motor/safety control isolated? A public reference target today is 128 GB-class high-bandwidth memory and 4 TB NVMe, with room to grow toward 256 GB+ and 8 TB+ as local model footprints evolve.

## Integration
Can these capabilities be exposed through modular interfaces so advances from different organizations can be evaluated together rather than requiring a monolithic vendor stack?

These questions are the public scope. Internal implementation choices remain outside this repository.
